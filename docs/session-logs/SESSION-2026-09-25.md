## 4. Decisions Made

1. **`startDate` UNIQUE constraint via migration, not `fallbackToDestructiveMigration()`** — Three duplicate `2026-09-02` rows existed in `period_entries`. The correct fix is a migration that cleans duplicates (keep latest per date) then adds the UNIQUE constraint, not a destructive rebuild. `fallbackToDestructiveMigration()` would wipe all user data on upgrade — never acceptable in production.

2. **`tryBind()` + 50ms debounce on Home screen** — Without this, six rapid LiveData emissions on startup (settings, prediction, logs all firing independently) caused six partial UI renders, the last of which could be blank if `settings` arrived after `prediction` cleared the existing render state. The debounce collapses all rapid fires into one render at the end.

3. **`rawCycleDay()` vs `cycleDay()`** — Added a private `rawCycleDay()` that returns the true elapsed days with no clamping. `cycleDay()` still clamps to `[1, cycleLength]` for ring display so the ring doesn't overflow. `isPeriodLate()` and `daysLate()` now use `rawCycleDay()` so a user who is 5 days late correctly sees "5 days late" instead of "Day 28" (the clamped maximum).

4. **Manifest `intent-filter` was the root cause of notifications never showing** — Alarms were scheduling and firing correctly (Logcat showed this) but the notifications never appeared on device. Root cause: `AlarmReceiver` and `PeriodConfirmReceiver` had no `intent-filter` in `AndroidManifest.xml`, so the broadcast Intent had no matching receiver registered — it was broadcast but nothing caught it. Adding the intent-filter immediately fixed all notification types.

5. **`onBackPressedDispatcher.addCallback()` replaces `onBackPressed()`** — `onBackPressed()` is deprecated on Android 13+. On some devices the exit dialog never showed because the deprecated method's behavior changed. The dispatcher-based approach is the correct API going forward.
