## 4. Decisions Made

1. **App name change instruction received** — Team lead directed the app name be changed from "LunaCycle" to "Period Tracker". This will be applied from the next working session. The package name `com.example.lunacycle` will also need updating (deferred — package rename requires more care).

2. **Period-end tracking feature** — Added `logPeriodEnd(date)` so the app learns actual period duration from user confirmation rather than waiting for the next period to start. Before this, `endDate` was only ever set when a new period was confirmed, meaning the app never knew the real duration of any period. Now the Home button changes to "My Period Ended Today" while a period is active.

3. **Three LogSymptomsFragment bugs fixed together:**
   - *Wrong date bug* — Calendar "Edit Log" was always saving to today's date regardless of which day the user tapped. Fix: read `ARG_DATE` from fragment arguments.
   - *Chips reset bug* — LiveData observer was firing mid-edit and resetting all chip selections back to the saved state. Fix: load existing log once using a one-shot coroutine instead of an ongoing observer.
   - *Duplicate entry bug* — Re-saving an existing entry created a new row instead of updating the existing one. Fix: store `editingEntryId` on open; call `updateDailyLog()` when editing, `saveDailyLog()` only for new entries.

4. **Onboarding footer fix** — The footer note was not pinning to the bottom on several screens because `layout_width="wrap_content"` with only `constraintStart` set. `constraintEnd` is also required for the horizontal chain to resolve and the view to stretch full-width before the bottom constraint can anchor it correctly.
