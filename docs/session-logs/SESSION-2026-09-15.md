## 4. Decisions Made

1. **Single-Activity architecture** — One `MainActivity` hosting four fragments via `BottomNavigationView`. Chosen because it simplifies the shared `CycleViewModel` (one scope for all screens) and avoids passing data between activities.

2. **CycleEngine as a pure Kotlin object** — No Android imports, no Context, no LiveData. Chosen so all cycle maths are unit-testable without an emulator or Robolectric.

3. **Room over DataStore for all user data** — DataStore used only for the onboarding-complete boolean flag. Everything else (settings, periods, logs) is in Room so it can be queried with SQL and observed reactively.

4. **CycleCalendarView as a custom View (not RecyclerView)** — Calendar month grids built with RecyclerView are hard to colour-code per cell without creating complex adapter logic. A single custom View with canvas drawing is 200 lines vs 600.

5. **App name: LunaCycle** — Working name chosen for the project. Package `com.example.lunacycle` at this stage.
