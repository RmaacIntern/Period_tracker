## 4. Decisions Made

1. **Multi-entry daily logs** — Changed `DailyLog` PrimaryKey from `date` to `entryId` (autoGenerate). Reason: one log per day is not enough — users may want to log morning BBT and evening symptoms separately. The `entryNumber` field tracks which entry it is in the day (1st, 2nd, etc.).

2. **Time-based entry labels, not count-based** — Entry label (Morning Log / Midday Log / Evening Log / Night Log) is now derived from the `loggedAt` timestamp hour, not `entryNumber`. Reason: three entries saved within 5 minutes all getting different labels ("Morning", "Midday", "Evening") was wrong and confusing.

3. **Period detection only on first entry of day** — `saveDailyLog()` only triggers the "should we start a new period?" check when `entryNumber == 1`. Reason: if the user logs flow a second time in the same day, it shouldn't create a duplicate period entry.

4. **Prediction hierarchy: BBT > cervical fluid > formula** — `bestPrediction()` in `CycleEngine` uses the most reliable signal available. If BBT thermal shift is detected it takes priority; if not, cervical fluid progression is used; if neither, the formula (lastPeriodStart + avgCycleLength) is the fallback. This will be revisited in SESSION-2026-09-24.md.
