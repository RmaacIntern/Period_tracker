## 4. Decisions Made

1. **Ads classes adapted from previous project, not written from scratch** — The six classes (`AdConstants`, `AdsRemoteConfig`, `BannerAdHelper`, `LoadAds`, `ShowAds`, `AppOpenAdManager`) were already written, tested, and working in another project. They were integrated here with three changes: (a) ad unit IDs replaced with this app's test IDs, (b) preload key names updated to match this app's contexts (splash, onboarding, shared), (c) Remote Config flag names and defaults updated. This saved approximately 2 days of development.

2. **Firebase Remote Config controls ads without an app update** — Every ad type has a boolean flag in Remote Config. Setting `show_banner = false` in the Firebase Console turns off banners for all users within ~1 hour, no APK update required. This is important because the app may need to quickly disable ads if an ad policy issue arises on the Play Store.

3. **Custom `BottomNavigationView` replacement** — The standard `BottomNavigationView` was drawing behind the fragment content. The custom layout gives precise control over: the selected tab gradient pill background, `INVISIBLE` (not `GONE`) labels so the layout width doesn't shift when a label appears, the icon tint per state, and the ability to intercept tab clicks to show an interstitial before navigating.

4. **`INVISIBLE` not `GONE` on nav labels** — When a tab is selected, its label becomes `VISIBLE` (white text, shown). When unselected, it becomes `INVISIBLE` (hidden but still occupies space). If `GONE` were used, the tab width would change when the label appeared/disappeared, causing the other tabs to visually shift. `INVISIBLE` reserves the space so the layout stays stable.

5. **Splash interstitial: single-shot load, not preloader pool** — The onboarding and main-activity interstitials use `InterstitialAdPreloader` (a pool that auto-refills). The splash interstitial uses `InterstitialAd.load()` (single-shot, consumed once). Reason: the splash interstitial fires exactly once per app launch. A pool is wasteful for a guaranteed one-time event. The splash ad is consumed by `pollSplashAd()` which sets it to null after retrieval.

6. **Back press click counter is SEPARATE from tab click counter** — `ShowAds.showBackPressAd()` does not share state with `showMainOnUserAction()`. This means ads on back press follow their own timing/click budget, independently of how many tabs the user has switched. This prevents a situation where a user taps 2 tabs then presses back and doesn't see the back-press ad because they "already used" 2 of their 3 clicks for tabs.

7. **Theme `windowTranslucentStatus` was inside `CycleChip` style** — This was breaking edge-to-edge display. The `windowTranslucentStatus=false` and `windowTranslucentNavigation=false` flags belong at the theme/activity level, not inside a widget style. Moved to `Base.Theme.PeriodTracker`.
