### 2a. Bottom Nav System Bar Fix

| File | Fix |
|---|---|
| `MainActivity.kt` — `setupWindowInsets()` | Added `systemBarBottom` field. `applyBottomInset()` checks banner visibility at runtime and routes system bar padding correctly. |
| `MainActivity.kt` — `applyBottomInset()` | When banner visible → banner gets `systemBarBottom`. When banner gone → nav bar gets `systemBarBottom + 10dp` (preserving XML padding). |
| `MainActivity.kt` — `onResume()` | Added `applyBottomInset()` call so padding re-checks on every foreground. |
| `activity_main.xml` | Changed from `ConstraintLayout` to `LinearLayout` — guarantees correct stacking order: content → nav → banner. |
| `small_banner.xml` | Root height changed from `match_parent` to `wrap_content` — was taking full height even when empty. Added `visibility="gone"` by default. |
| `custom_bottom_nav.xml` | Changed fixed `64dp` height to `wrap_content` with `minHeight="64dp"` so `setPadding()` can add system bar gap correctly. |

**Final padding logic:**
```
Banner VISIBLE → nav padding = (8dp, 10dp, 8dp, 10dp)
                 banner padding = (0, 0, 0, systemBarBottom)

Banner GONE   → nav padding = (8dp, 10dp, 8dp, 10dp + systemBarBottom)
                 banner padding = (0, 0, 0, 0)
```

### 2b. App Open Ad Preload Fix

| File | Fix |
|---|---|
| `AppOpenAdManager.kt` — `startPreloading()` | Removed `if (isPreloadStarted) return` guard that prevented reloads. |
| `AppOpenAdManager.kt` — `onAdsExhausted()` | Added `isPreloadStarted = false` + `startPreloading()` call so buffer refills after being polled. |
| `AppOpenAdManager.kt` — `onAdDismissedFullScreenContent()` | Added `isPreloadStarted = false` + `startPreloading()` so next ad preloads immediately after dismiss. |
| `AppOpenAdManager.kt` — `onAdFailedToShowFullScreenContent()` | Same restart logic added. |

**Root cause:** `pollAd()` removes ad from buffer. `onAdsExhausted()` fired but `isPreloadStarted = true` caused `startPreloading()` to return immediately. Ad never reloaded → only one ad per session.

**Also:** `MIN_INTERVAL_MS` discussion — set to `0L` to show on every foreground, or `30 * 1000L` (30 seconds) as safe minimum.

### 2c. Fragment Bleed-Through Fix

**Problem:** Opening `PastLogHistoryFragment` from Insights, then tapping Home tab showed Insights content behind Home. Same with `LogSymptomsFragment`.

| File | Fix |
|---|---|
| `MainActivity.kt` — `onTabClicked()` | Changed `popBackStack()` → `popBackStackImmediate()` (synchronous). Added `hideTx` block that hides ALL fragments immediately after pop, before tab switch. |
| `MainActivity.kt` — `showTab()` | Changed `commitNowAllowingStateLoss()` → `commitNow()` — executes hide/show on same frame, no gap where old fragment is visible. Added `!fragment.isHidden` check before hiding. |

**Root cause:** `replace()` transaction restores previous fragment when backstack pops. Old code only hid 4 known tab fragments by tag — missed the restored fragment. `popBackStack()` is async — old fragment still visible when `showTab()` ran.

### 2d. PDF Dialog Fix

**Problem:** Tapping Download Report → interstitial shows → PDF dialog never appeared after ad dismissed.

**Root cause:** PDF generation used `viewLifecycleOwner.lifecycleScope` which pauses when interstitial activity is on top. By the time coroutine resumed, `parentFragmentManager.isStateSaved` was true, blocking dialog.

| File | Fix |
|---|---|
| `InsightsFragment.kt` — `exportPdf()` | Changed `viewLifecycleOwner.lifecycleScope` → `requireActivity().lifecycleScope` — activity scope survives while ad shows. |
| `InsightsFragment.kt` — `openSheet()` | Removed `parentFragmentManager.isStateSaved` guard — was blocking dialog. Removed lifecycle state check — was returning early while ad activity on top. |
| `InsightsFragment.kt` — `bindClickListeners()` | Moved ad to AFTER PDF generation. Order was: tap → ad → generate → dialog (dialog failed). Now: tap → generate → ad → dialog (dialog works). |
